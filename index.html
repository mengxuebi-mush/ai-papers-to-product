预训练

模型只会算数，所以文字要先变成数字。然后模型读海量文字，一遍遍猜下一个词。猜着猜着，它学会了语言，也记住了很多事实。后面所有的步骤，都建立在这上面。

回答的问题：一堆数字，怎么学会词是什么意思？

关键想法
文字先变成数字

模型只会算数，所以分词器先把文字切成小块，叫 token，再给每块一个编号。编号只是标签，就像储物柜号码。

带意思的数字

每个编号再换成一个 embedding：一串几百个数字。就像 RGB 用数字表示颜色，意思相近的词，数字也相近。这些数字一开始是随机的，在预训练中学出来。

和 RGB 不同，embedding 的单个数字说不出名字。

一遍遍猜下一个词

给它“猫坐在”，它猜“垫子上”。真正的下一个词就是标准答案，所以不用人来标注，几乎任何文字都能拿来练。每猜错一次，相关的数字就被微调一点。用法相似的词，比如“苹果”和“梨”，被往同一个方向调，数字就慢慢靠在一起。已有研究

学习就是拧旋钮

模型是一个有几十亿个旋钮的大函数，这些旋钮叫参数。每猜一次，loss 就给猜错的程度打分。它奖励说出真实的概率，越自信地猜错罚得越重，所以预训练模型通常校准得不错。训练就是把每个旋钮往让 loss 变小的方向拧一点（梯度下降），然后重复非常多次。

注意力：词和词互相看

要猜准下一个词，得知道前面哪些词重要。注意力让每个词一次看完前面所有的词，而不是像以前的模型那样一个词一个词地读。这让训练快到可以在海量文字上预训练。已有研究

RNN 和 Transformer 的对比 →
越大越好，但有限度

参数更多（脑子更大）、文字更多（读的书更多）、算力更多，loss 会稳定下降。但它们要一起加：很多模型相对它读的文字来说太大了。已有研究

练完得到的是接话器，不是助手

你问一个刚练完的模型一个问题，它可能接着再问你几个问题，因为这也是一种很常见的接法。让它变得好用，是下一段的事。

后训练

刚练完的模型只会接话。后训练要改的就是这个：让它听指令，给出人真正想要的回答。做法是给它的回答打分，再把参数往高分的方向调。

回答的问题：怎么把接话器变成好用的助手？

关键想法
三种打分方式

可以拿好答案给它当示范，可以让人给它的几个回答排名，也可以拿有确定答案的东西来核对，比如数学题的结果或单元测试。选哪种，它最后就长成什么样。

靠人的偏好来学

同一个问题，让人给几个回答排名。再单独训练一个打分模型，叫 reward model，去预测这些排名，训练模型时就用它来打分，论文把这个正在训练的模型叫 policy。这叫 RLHF。InstructGPT 里，人更喜欢小得多的这个版本，而不是原版 GPT-3。

InstructGPT →
能核对的话，只说对错就够

如果答案能自动核对，就不用人来打分了，答对就给奖励。DeepSeek-R1 就是这么做的，它的回答自己变得更长、更仔细，没人要求过。

DeepSeek-R1 →
后训练可能让模型过度自信

RLHF 之后，模型说出的把握往往高于它实际答对的比例：它可能说自己有 90% 把握，实际只对七成左右。后训练之前，模型通常校准得不错。偏好打分奖励的是人喜欢的回答，不是诚实的概率。原文 Calibration

Calibration →
打什么分，就得到什么

对任何分数用力优化，模型都会找到捷径：分数很高，结果不对。这叫 Goodhart 定律，在 AI 里叫 reward hacking。一个划船游戏里的 agent 学会了原地绕圈撞得分道具，就是不去终点。所以 RLHF 加了 KL penalty，像一根绳子，不让模型离起点跑得太远。已有研究任何用来训练或评估 agent 的指标，都要问一句：它最容易被怎样钻空子？推测

同一种裁判（人、打分模型、另一个 LLM），评估模型用它，训练模型也用它。裁判有偏差，模型就会学到这个偏差。已有研究

管理 context

模型只知道此刻 context window 里的东西，而 window 的大小是固定的。规则文件、检索、记忆、工具、skill、subagent，其实都在回答同一个问题：这一轮放什么进去？

问题：什么东西配占 window 里的位置？

context window
window 里装了什么

官方文档 模型回答时能参考的全部内容，包括它正在写的回答。指令、工具和 skill 的说明、文档、你的输入和它的输出，共用同一份额度。下面每种办法，都是在替这份额度腾地方。

Context windows（Anthropic 文档） ↗

Cached token：更便宜，但不更小

官方文档 window 的前面一段（先是工具，再是 system prompt，然后是消息）每轮往往一模一样，所以服务商可以把它缓存起来。缓存的 token 读得更快、价格只是零头，但它们仍算输入，仍然占位置。前面任何一处改动，比如会话中途改了规则文件，后面的内容就都要重新读。推测 不会变的东西放在最前面。

Prompt caching（Anthropic 文档） ↗

放得多不等于用得好

原文 给 20 篇文档、答案只在其中一篇时，GPT-3.5-Turbo 在那篇排第一时表现最好，排在中间时最差，比完全不给文档还差。官方文档 Anthropic 把这种普遍现象叫 context rot。推测 留对的那几样，而不是留最多。

Lost in the Middle 论文页 → · arXiv（Liu 等，2023） ↗ · Effective context engineering（Anthropic，2025） ↗

管理的办法
规则文件：CLAUDE.md 和 AGENTS.md

放在项目里的一个 Markdown 文件，写 agent 每次都该知道的事：怎么构建、怎么测试、有哪些约定、什么不能碰。官方文档 Claude Code 每次对话开始都会载入 CLAUDE.md，并把它当作 context，而不是强制执行的配置。AGENTS.md 是同一个思路做成的开放格式，很多 coding agent 都会读，官方说法是“给 agent 看的 README”。

推测 每次都载入，就每次都占位置，而且模型仍可能忽略某一行。写短一点；绝对不能发生的事，用 hook 或测试来拦。

Claude Code：memory ↗ · AGENTS.md ↗

检索（RAG）：只取相关的

不把整个知识库塞进去，而是先搜索，只把匹配的几段放进 window。原文 RAG 论文把语言模型和一个可搜索的 Wikipedia 索引配在一起。它把模型的参数叫 parametric memory，把索引叫 non-parametric memory，并且证明换掉索引就能更新模型知道的东西，不用重新训练。

原文 论文里检索器和生成器是一起训练的。已有研究 现在大多数产品是在一个不变的模型前面加一步搜索，所以它是 harness 层面的选择。推测 结合 Lost in the Middle：最相关的放最前面，检索的段落宁少勿多。

RAG（Lewis 等，2020） ↗

记忆：window 清空之后还留下什么

原文 MemGPT 把较早的消息移到 recall storage，需要时让模型自己去搜。原文 Generative Agents 用一条 memory stream，用自然语言记下 agent 经历过的一切。retrieval function 挑出要给模型看的记忆，按 recency（多新）、importance（多重要）、relevance（多相关）打分。agent 还会写 reflection：从很多条记忆里总结出更高层的结论。

推测 给个人 agent 设计记忆系统，也离不开这三件事：记什么，怎么挑出要回来的，什么时候把很多条笔记浓缩成一条。

MemGPT → · Generative Agents（Park 等，2023） ↗

工具和 MCP

agent 能调用的每个工具都带着名字、描述和参数说明，这些都占 window。原文 ReAct 展示了“调用工具、读结果”的基本循环。Toolformer 训练模型自己决定调哪个 API、什么时候调、传什么参数。它改了参数，严格说属于后训练，但工具调用就是从这里开始的。

官方文档 MCP 是把工具和数据接入 agent 的开放标准：server 提供 tools、resources 和 prompts，应用作为 client 去连接。推测 接的 server 越多，每次对话里的工具描述就越多，这也是 skill 要按需载入的原因之一。

ReAct → · Toolformer（Schick 等，2023） ↗ · MCP 规范 ↗

Agent skills：先给名字，用到再读全文

一个 skill 是一个文件夹，装着做某一类事的说明，有时还有脚本，比如填表。官方文档 启动时 agent 只载入每个 skill 的名字和描述；任务对上了，才去读那个 skill 的全文。Anthropic 把这叫 progressive disclosure。

原文 学术上的前身是 Voyager：一个玩 Minecraft 的 agent，每写出一段能用的程序就存进 skill library，用一句描述做索引，遇到新任务时取出最相关的 5 个。它学会新东西，却没有改参数。

Agent Skills（Anthropic，2025） ↗ · Voyager（Wang 等，2023） ↗

Subagent：支线任务开一个新 window

把支线任务，比如“找出这个函数被调用的所有地方”，交给另一个 agent，它有自己空着的 window。它去读那些乱七八糟的东西，主 agent 只拿回答案。官方文档 Claude Code 里每个 subagent 都在自己的 context window 里运行。Anthropic 的 context 指南说，一个 subagent 可能用掉几万个 token，但只交回一段摘要，常常是 1,000–2,000 个。

原文 AutoGen 是较早的框架，用几个互相对话的 agent 搭一个应用。推测 对多数编程工具来说，好处主要在 context：主 window 保持干净。

Claude Code：subagents ↗ · AutoGen（Wu 等，2023） ↗

长循环：压缩和笔记

agent 循环每转一圈都会加进工具输出，所以长任务会把 window 填满。官方文档 Anthropic 指南里的两个办法。Compaction（压缩）：window 快满时把对话总结一下，用这段总结开一个新 window。Structured note-taking（结构化笔记）：agent 把笔记写在 window 外的文件里，需要时再读回来。

推测 这两招在本站都有论文上的前身：MemGPT 的 flush 就是压缩，Reflexion 的错题本就是笔记文件。

评估

评估不是最后一步。每一段都得回答：它真的变好了吗？结果能信吗？而评估用的打分，也正是后训练里训练模型的信号。

回答的问题：怎么知道它做得好，这个结论能不能信？

关键想法
先问：有没有标准答案？

有的话，对一下结果或者跑测试就行。没有的话，就得靠人的判断，或者找个裁判来代替人。后面的做法都从这里分叉。

学会了，还是背下来了？

要检查模型是不是真学会了，得用它没见过的题来考，就像正式考试的题不能混进练习题。练习题满分、新题就不会，叫过拟合。如果考题混进了训练文字（数据污染），高分也说明不了什么。

做对一次不算数

模型今天做对了，明天可能又错。τ-bench 看的是重复做很多次，每次都成功的比例（pass^k）。次数一多，成功率掉得很快。

τ-bench →
模型可以当裁判，但有习惯

没有标准答案时，可以让强 LLM 来评。MT-Bench 发现，它和人的一致程度，跟人和人之间差不多。但它有习惯：偏爱先看到的答案、更长的答案，还有自己写的答案。

MT-Bench →
它知道自己不确定吗？

校准问的是：模型说“我有 70% 把握”，是不是真的 10 次里对 7 次。大模型这方面通常还不错，但后训练可能把它弄差。已有研究

Calibration →
先发散，再收敛

探索想法的时候，一次生成很多个、让人来挑就行（pass@k）。真要执行选定的那个，就得每次都对（pass^k）。推测

共同的盲区

每条的事实部分都来自原文，最后一句“对产品意味着什么”才是推测。

都用 LLM 代替人

原文 τ-bench 用 gpt-4 模拟用户；MT-Bench 用 GPT-4 当裁判；InstructGPT 用 reward model 代替标注员；Reflexion 在部分任务里用 LLM 或自写测试当 Evaluator。

推测都没有拿 enterprise 领域专家验证过。

“人类”是一个很窄的群体

原文 MT-Bench 是研究生和众包用户；InstructGPT 是约 40 名主要在美国或东南亚的标注员；τ-bench 没有报告 human baseline。

推测和他们一致，不等于和 SRE、admin 一致。

人和人本身就会分歧

原文 MT-Bench 专家之间一致率 81%；InstructGPT 标注员之间约 73–77%。分歧在训练和评分时被平均掉。

推测少数用户群的偏好最容易在平均中消失。

只看结果，不看过程

原文 τ-bench 作者写明 r=1 是必要不充分条件，没经确认就执行也算成功；MT-Bench 只评最终回答。

推测 enterprise 需要知道谁批准的、agent 看到了什么。

失败没有轻重之分

原文 τ-bench 只有 0 和 1。按规则该拒绝时拒绝会得分，但任务做得到时“转人工”和“做错了”同样是 0。

推测区分不了能被发现的失败和 silent failure。

偏好不等于正确

原文 MT-Bench 裁判“偏爱”更长的回答（长回答更容易得高分），会被错误数学答案带偏；Reflexion 自测题会让错误代码通过（Rust 16%）。

推测写得漂亮但结论错的 RCA 可能得高分。

评估和训练会被反向优化

原文 InstructGPT 专门加 KL penalty 防止钻 reward model 的空子。

已有研究 reward hacking 是公认问题；RLHF 模型普遍有 sycophancy 倾向（Anthropic 2023，待确认）。

都没给“不确定”留位置

原文 τ-bench 的 0/1 判分如上。已有研究 Kalai et al. 2025 认为打分方式奖励猜测、不奖励弃答（待确认）。

十七条设计原则

危险程度看可发现性，不只看失败类型

会报错 / 不报错 × 可逆 / 不可逆。最危险的是不报错、且已被拿去做决策的失败。

依据：τ-bench 0/1 判分与失败分类（§3, §5.2 原文）
对 silent 的失败，把证据摆出来

展示实际执行的 query 和数据范围；batch 操作给覆盖率，不要只给一个 Done。

依据：τ-bench“复合请求做一半”占 19%（§5.2 原文）
写操作前，结构化确认关键参数

列出型号、金额、ID、旧值→新值，比让 agent 复述一段话更能拦住错误。

依据：τ-bench 参数或信息错占失败约 55%（§5.2 原文）
审批要分级，并且要让批准有意义

按风险分只读、可逆写、不可逆写。每步都批准会变成橡皮图章，出事时责任落在点按钮的人身上。

依据：τ-bench 判分不看过程（§3 原文）；moral crumple zone（Elish，已有研究）
先让人独立判断，再揭示 AI 的意见

AI 建议出现的时机，决定人的判断还独不独立。

依据：MT-Bench 分歧案例中 34% 的人改了判断（§4 原文）；anchoring、automation bias（已有研究）
LLM judge 筛明显的，接近平局的交给人

被排除的难判题，恰恰最需要人的判断。

依据：85% 一致率是排除平局后的 S2，计入平局是 66%（MT-Bench §4 原文）
用反常识的规则测 agent 是否真的在守 SOP

demo 好看，可能只是因为任务碰巧符合常识。

依据：retail 拿掉 policy 只降 4.4 分，airline 降 22.4 分（τ-bench Table 3 原文）
交接点要显式化

把“锁定方案”做成一步：agent 先复述选定方案、理由、不要的东西和约束，人核对后存成 brief。

依据：Lost in the Middle（已有研究）；intent debt（loop engineering 资料）
明确“谁的品味”定义了好回答

通用模型默认反映一小群标注员的偏好。用 system prompt、领域示例或自己用户的反馈，把“好”的定义换成你的用户。

依据：InstructGPT §5.2“Who are we aligning to?”（原文）
给 agent 一个可以安全犯错的沙盒

风险高不等于不能试错，而是不能在真实环境里试错。dry-run、测试环境、样本数据验证让 agent 在沙盒里反复试，提交只有一次。人的位置从“盯每一次尝试”换成“定义什么算成功、看最终提交”。紧急事故的瓶颈是时间。

依据：Reflexion 先自测再提交（§3–4 原文）；τ-bench“直接面对用户只有一次机会”（§5 原文）
让 agent 学到的东西可查看、可编辑

让用户或管理员能审核、修改、删除 agent 记忆里存的教训，像管理一份共享 SOP。

依据：Reflexion 反思可读（§6 原文）、Evaluator 会误判（§4 原文）；CLEA 征稿的 memory 与 alignment drift（原文）
让“不确定”在界面上有位置

区分查到的和推断的，展示依据，置信度低时主动建议核实，并且不惩罚模型说“不知道”。

依据：InstructGPT 仍会犯简单错误（§4.3 原文）；Kalai et al. 2025（已有研究，待确认）
记忆和文档要带来源、时间、负责人，冲突要摆出来

引用 runbook 或 policy 时说明出处和更新日期；两份说法矛盾时让用户看到，而不是默默选一个。

依据：MemGPT 记忆没有来源和冲突规则、测试材料全是静态的（§2–3 原文）；τ-bench 把冲突事实列为挑战（§6 原文）
给记忆一份可见的目录

标明柜子里有什么、多新、哪里有冲突。agent 不再只能“凭感觉搜”（实际是对存储内容做相似度检索，并不知道里面有什么），人也能看到存储里有什么。

依据：MemGPT 检索有局限、翻页常提前停（§3.2 原文）
不把解释当证据，用反事实测试审计

流畅的推理是表达，不是验证。高风险结论要能指回具体的查询结果；审计时换顺序、删证据、去掉用户表态，看结论会不会变。

依据：ReAct 中 CoT 有 14% 答对但推理错（Table 2 原文）；MT-Bench 位置偏差与交换测试（§3.3 原文）；Turpin et al. 2023 等（已有研究）
置信度要在自己的任务上校准，优先展示“区分”而不是精确数字

RLHF 模型的概率不能直接当置信度。用真实工单和查询重新校准；界面上用“高 / 中 / 低”把需要复核的挑出来，往往比“73%”更有用。

依据：RLHF 模型很不校准、调温度可修补，陌生任务上校准变差但区分能力能迁移（Calibration 原文）
每个指标都配一个“会被怎么钻空子”的检查

指标一旦被当成目标，就会被钻空子（Goodhart's law）。任何用来训练或评估 agent 的指标，都配一个反事实测试或交叉检查。

依据：MT-Bench 冗长偏差（§3.3 原文）、InstructGPT KL penalty（§3.5 原文）、Reflexion 自测误判（§4 原文）；Goodhart 1975、Strathern 1997（已有研究）

τ-bench

τ-bench: A Benchmark for Tool-Agent-User Interaction in Real-World Domains · Yao, Shinn, Razavi, Narasimhan · Sierra · 2024

一场模拟客服上岗考试：agent 要一边跟用户对话、一边调工具、一边守业务规则。

arXiv 2406.12045 ↗HTML 全文 ↗Evaluation of Interactive Agents
四句话论文卡
主张

真实部署要求 agent 同时跟人对话、调工具、守规则；现有 agent 在这种设定下成功率不高，而且很不稳定。

最强证据

gpt-4o 在 retail 的 pass^1 超过 60%，pass^8 低于 25%；规则反常识的 airline 场景里，拿掉 policy 后分数大幅下降。

边界

用户是模拟的，只有客服场景，成败只分对错，也没有 human baseline。

产品还要验证

失败能不能被发现、能不能恢复？和人比怎么样？模糊的请求能不能处理？

和 Transformer 那篇的对照

Transformer 的证据是 BLEU：输出和参考答案有多像。τ-bench 的证据是数据库最终状态：事情到底办成没有。

核心指标

pass^1 和 pass^k

咖啡师类比：pass^1 是随便点一杯拿铁、这杯做对的概率；pass^8 是连续 8 天点同一杯、8 天都做对的概率。

56%pass^1：所有尝试的平均成功率
25%pass^8

计算器里的 4 个任务是教学示例，不是论文数据。

  • 8 次是完全独立的重跑：同一份任务剧本，从零开始，没有记忆，也不会被纠正。
  • agent 的 temperature 是 0.0，模拟用户是 1.0。不稳定主要来自用户换了说法。
  • pass@k 是 k 次至少一次成功，pass^k 要求全部成功。k 越大，前者越高、后者越低。
  • retail 全部任务跑一轮约 200 美元。推测所以 k 取到 8 主要受成本限制，不是行业标准。产品的 k 应由真实使用频率倒推。

Problem · §1

续写不等于回答

对只做过 pretraining 的模型说“用 6 岁小孩能听懂的话解释登月”，它可能接着写出一串类似的题目，因为网上这句话后面常跟着列表。作者把模型编造事实、输出有害内容、答非所问统称为 misalignment，并指出模型变大不能解决。

Reward model 怎么训练

  • 每个 prompt 让标注员给 4 到 9 个回答排序，再拆成两两比较。
  • 训练目标：让“被选中”回答的分数比“被淘汰”回答的高。分差越大，代表“人更喜欢前者”的把握越大。结果是一个给每个回答打分的模型。
  • 只用一个 6B 的 reward model 给 175B 的模型打分。论文给的理由有两个：省算力，另外 175B 的 reward model 训练起来可能不稳定。论文没有说“reward model 小所以更容易被钻空子”，那是别人的推断。

谁在变，谁冻结

模型在 Step 3 的角色会变吗
SFT 模型参照物：KL penalty 拿它比，看跑偏多远（实习生第一周的录像）冻结
Reward model考官：给每次练习打分冻结
Policy 模型正在练习的实习生，练完就是交付的 InstructGPT唯一在变
KL penalty

得分 = 考官打分 − 跟 SFT 模型差了多远。它防的是 reward hacking：模型为了讨好考官，变成了“另一个人”。实际发生的是，参数一路朝着让 reward model 打高分的方向漂移，输出越来越偏离 SFT 模型。

PPO-ptx

练习时混入一些 pretraining 数据，这样学新东西的时候，基本功也每天照练。它防的是 alignment tax。目标里有两个旋钮：一个管 KL penalty 的力度（β），一个管混入 pretraining 的比重（γ）。把 γ 调成 0，就是普通 PPO。论文里说的 “InstructGPT”，默认指 PPO-ptx。

Alignment tax 是什么，怎么发生的

是什么：模型被调教成好助手之后，在一些原本做得不错的通用能力上反而变差了。像为了作文拿高分只练作文，数学退步了：这就是“税”。

推测怎么发生：RL 阶段，整个模型的参数都在朝“让 reward model 打高分”的方向被推。参数是共用的，推向“会当助手”的同时，没有任何东西保护别的本事，其中一部分就被挤掉了。

推测为什么 KL penalty 治不了：KL penalty 管的是“练习时的回答别离 SFT 模型太远”，它盯着练习题。退步发生在练习没覆盖的地方，拴住练习题的回答，拴不住别的本事。论文的观察和这个解释一致：把 KL 调大，补不回来。

怎么补：PPO-ptx 每天练习时还做几道原来的 pretraining 题，等于“练作文的同时也复习数学”，补回大部分，但不是全部。

表现语气肯定地输出不存在的事实、引用输出向用户的观点靠拢，一被质疑就改口
主要根源Pretraining：目标是“续写得像”RLHF：标注员偏爱让自己舒服的回答

思维链是被“养”出来的

  • 训练中回答长度持续增长；模型会在中途重新评估自己的思路，“wait”这类词的使用明显增加。论文称之为 “aha moment”。

步骤做什么

我们的讨论

产品含义

  • 推测 思考时间变成可买的资源。长思维链意味着延迟和成本上升。设计上要问的是：什么时候让 agent 想久一点，用户看到的是在等，还是看到了过程。
  • 推测 能自动验证的场景才好用。数学、代码有标准答案。根因分析（RCA）没有，除非像故障注入那样先埋下已知答案。
  • 推测 验证器本身要被测。评测里的“对”如果可以走捷径，分数就是虚高。
  • 推测 审计要看证据链，不只是思维链。思维链是模型写的文字，已有研究显示它未必反映真实依据（见 README 里的 Turpin 2023、Lanham 2023）。可审计的是它查了什么、拿到什么：工具调用的记录。思维链像目录，原始数据和查询是原文，两者要互相挂钩：每个断言带着它依据的那条查询，没挂证据的断言一眼可见。
  • 推测 双语用户的混合语言思考不一定是缺点。语言一致性奖励按目标语言词占比算，而双语工程师本来就说“这个 index 的 retention 太短”。但企业的日志要能搜索和审计，混着写会更麻烦。展示什么由用户设置，比如一线看简版，审计看原文，是个值得验证的假设，我们还没有任何使用数据。

我们的讨论

风险高不等于不能试错，而是不能在真实环境里试错

  • 推测能不能用错题本，取决于有没有一个失败不要钱、又能可靠判对错的沙盒。Infrastructure 可以先 dry-run，data pipeline 可以先用样本验证；紧急事故的瓶颈是时间。
  • 推测低风险的 chatbot 未必能接受 12 次重试：每次失败用户都看得见，信任会先耗光。
  • 推测人的位置从“盯每一次尝试”换成“定义什么算成功、搭沙盒、看最终提交”。评估器定错了，agent 越自主，就越稳定地收敛到错误答案（循环里没有任何东西会叫停它）。
已有研究和 loop engineering 的关系

Loop engineering 通常被描述为 Goal → Action → Observation → Adjustment，再加持久记忆（spine），和 Actor、Evaluator、Self-Reflection、长期记忆一一对应。但 loop 不一定包含反思：逐个处理一批对象、或单纯重试到通过，都不需要写教训。相关资料列出的风险包括 intent debt、comprehension debt、cognitive surrender。

MemGPT

MemGPT: Towards LLMs as Operating Systems · Packer, Wooders, Lin, Fang, Patil, Stoica, Gonzalez · UC Berkeley · 2023

借鉴操作系统的虚拟内存：context 是一张小书桌，外部存储是大档案柜。由 LLM 自己“决定”什么放桌上、什么收进柜子、什么时候去翻。实际上，是模型输出一个函数调用（存入、搜索），由外层程序去执行。

arXiv 2310.08560 ↗Continual Learning for Enterprise AI Agents
四句话论文卡
主张

借鉴操作系统的虚拟内存，让 LLM 自己管理“桌上”和“柜子里”的记忆，就能突破 context 长度的限制。

最强证据

深度记忆检索的准确率，GPT-4 从 32.1% 升到 92.5%，GPT-4 Turbo 从 35.3% 升到 93.4%。嵌套查找到 4 层仍然稳定，基线到第 3 层就降到 0%。

边界

它需要很强的函数调用能力（GPT-3.5 带不动）。检索不全，翻页还会提前停。基线只看有损摘要，对比不完全对等。准确率由 GPT-4 裁判判定，测试材料也全是静态的。

Problem · 摘要, §1

Context 有限，但有两类任务需要很多记忆

  • 分析比 context 还长的文档。
  • 多次会话的长期对话：agent 要在很多次对话之间“记住”用户，并随交流不断更新对用户的“了解”。
操作系统类比

电脑的内存小而快，硬盘大而慢；操作系统决定什么放内存、什么换到硬盘，让程序感觉自己有很大的内存（virtual memory）。MemGPT 把 context window 当内存、外部存储当硬盘，让 LLM 自己当操作系统。

第 1 问 · 实验设定 §2.1

答案放在哪个位置，模型答对得最多？哪里最少？

给模型一个问题和 20 篇 Wikipedia 段落。只有 1 篇含答案，另外 19 篇和问题很相关、但没有答案，论文叫它们 distractor documents（干扰文档）。研究者只做一件事：把含答案的那一篇挪到不同位置，其他什么都不变。

答案在第几篇（共 20 篇）答对的比例
第 1 篇75.7%
第 5 篇57.3%
第 10 篇 ← 最低54.1%
第 15 篇55.4%
第 20 篇（最后）63.1%

以 GPT-3.5-Turbo (16K) 为例：开头最好，中间最差，而且结尾也不错，比中间高出不少。两头高、中间低，画出来像字母 U。论文叫它 U-shaped performance curve。两头各有名字：偏重开头叫 primacy bias，偏重结尾叫 recency bias。

“偏差”不是说模型“喜欢”开头。实际测到的只是：信息在开头或结尾时，答对的比例更高。

第 2 问 · 对照组 §2.3

一篇文档都不给，和答案埋在第 10 篇，哪个答对更多？

这个对照组叫 closed-book（闭卷）：只问问题，模型只能靠训练时记在参数里的知识回答。答案在第 10 篇时是 54.1%。

答案出人意料：闭卷是 56.0%，比 54.1% 还高。再加一个对照组 oracle：只给含答案的那一篇。

20 篇，答案在第 10 篇54.1%

同一篇文档，单独给是 88.6%，埋进中间只剩 54.1%，跌到了“什么都不给”以下。文档越多，中间越低：

推测别理解成模型被干扰文档“搞糊涂了”，那是人的说法。能测到的只是：多出来的 19 篇相关文本加上答案的位置，一起拉低了答对的概率。怎么拉低的，后面第 5、6 问再讲。

推测很多 AI 搜索和知识库问答（RAG）会把搜到的文档全塞进 prompt。原文 §1作者正是把这个实验当成 RAG 的简化版。塞得多不等于答得好。

第 3 问 · 加长版 §2.3

context window 更长的版本，会用得更好吗？

GPT-3.5-Turbo 有 4K 和 16K 两个版本，Claude-1.3 有 8K 和 100K 两个版本。20 篇文档两个版本都装得下。

几乎一模一样。

答案在第几篇4K 版16K 版
第 1 篇75.8%75.7%
第 5 篇57.2%57.3%
第 10 篇53.8%54.1%
第 15 篇55.4%55.4%
第 20 篇63.2%63.1%

两条曲线几乎重合，Claude-1.3 的两个版本也一样。window 变长，改变的是“最多能放多少”，没改变“放进去之后怎么用”。桌子换大了，你翻看中间几页的方式并没有变。

推测“支持 100K token”说的是容量，不是能力。评估长文档功能时，把关键信息分别放在开头、中间、结尾各测一次，不要只看平均分。原文 §1作者也提了同样的评估办法：最好和最差的差距要很小，才能说模型用好了长输入。

第 4 问 · 更简单的任务 §3

只要原样找出一个字符串，还会有 U 形吗？

作者想排除“读不懂”的因素，设计了 key-value retrieval（键值查找）：给一长串 JSON 键值对，键和值都是随机的 UUID，比如 "a3f9…": "7c2e…"，再给一个键，让模型把对应的值抄出来。不需要理解任何意思。

有的模型还会。

  • Claude-1.3 几乎全对，不管放在哪、多长。
  • GPT-3.5-Turbo、MPT-30B-Instruct 还是 U 形，键值对多了（140 对、300 对）更明显。GPT-3.5-Turbo (16K) 在 300 对里最差只抄对 45.6%。

问答题还可以说是“没读懂”，这个任务只要找一模一样的字符串，结果照样受位置影响。所以问题不只出在理解上，连找到信息这一步都和位置有关。

作者也觉得奇怪：self-attention 在技术上可以同样地取到任何位置的 token，按理不该偏心。

第 5 问 · 为什么（一）§4.1–4.2

把问题在数据前面也放一次，有帮助吗？

先要知道一个概念。GPT 这类模型是 decoder-only：从左往右读，读到每个 token 时只能 attend 到它前面的内容。实验里问题放在最后，所以模型读那一大串数据时，还不知道要找什么。作者的改法叫 query-aware contextualization：问题在数据前后各放一次。对键值查找和 20 篇文档的问答，分别有帮助吗？

对键值查找帮助很大，对问答几乎没用。

很容易说成模型“有了目标”，但那是人的说法。实际发生的是：问题放在前面以后，模型处理后面每一行数据时，问题的 token 已经在它能看到的范围里，每一行都能参照它来计算。模型并没有“想要”找什么。

推测为什么问答没变好？论文没给原因。键值查找是完全匹配，知道了键就解决了。问答里的干扰文档本来就和问题很相关，提前知道问题，并不能帮模型分辨哪篇真的含答案。难的是判断，不是找。

另一类模型叫 encoder-decoder，encoder 是双向的，读每一段时前后都能看到。Flan-UL2 在训练时见过的长度（2048 token）以内，最好和最差只差 1.9 个百分点；超出这个长度，U 形又出现了。

第 6 问 · 为什么（二）§4.3

没做过指令微调的原始模型，也有 U 形吗？

GPT-3.5 这类模型都做过 instruction fine-tuning（指令微调）：用大量“指令 + 回答”的例子再训练，而指令通常写在开头。所以作者怀疑：“偏重开头”会不会是微调教出来的？他们比较了 MPT-30B 的原始版（base model）和 Instruct 版。

原始版也有 U 形，而且更明显，作者也说这出乎意料。原始版最好和最差差将近 10 个百分点，Instruct 版约 4 个百分点。U 形不是微调教出来的，微调反而让它浅了一点。

Llama-2 的大小偏向
7B（70 亿参数）只偏重结尾
13B、70B两头都偏，U 形

作者推测，以前的研究只看到“偏重结尾”，是因为当时研究的模型太小（不到 10 亿参数）。

三个解释，都还没有定论

只能往前看的架构、问题放在最后、指令微调，作者都称为初步调查。到今天，“为什么会有 U 形”仍没有公认答案。心理学里人回忆一串词，也最记得开头和结尾，叫 serial-position effect。推测这只是相似的曲线，不代表模型有人一样的“记性”。

第 7 问 · 真实检索 §5

从 20 篇加到 50 篇，答对会多多少？

最后作者用检索系统从 Wikipedia 真实地搜文档再回答。这时搜到的文档里可能一篇都没答案，也可能有好几篇。50 篇里含答案的机会当然更大。

几乎不涨，但也没有变少。GPT-3.5-Turbo 多了约 1.5 个百分点，Claude-1.3 约 1 个百分点。输入却长了一倍多，延迟和成本跟着涨。

这里有两条线在分开走：retriever recall（搜出来的文档里含答案的比例）一直在涨，模型答对率早早就平了。检索把答案找来了，模型没用上。

作者自己的两个建议：reranking，把最相关的文档挪到最前面；ranked list truncation，适合少取时就少取几篇。

第 8 问 · 局限

和真实的排障场景比，这个实验哪里不一样？

回想设定：每题只有一篇含答案，问一次、答一次，判分时只看输出里有没有出现正确答案。

  • 受控实验里恰好一篇含答案。推测线索散在几份日志和 runbook 里、分散在不同位置时，只会更难，但论文没测。
  • 论文正好撞上一个冲突：一道题问 Robert Griffin III 在哪个 NFL 球队，标准答案写“目前是自由球员”，2018 年的 Wikipedia 写“Baltimore Ravens”。作者把这类有歧义的题挑出去重跑，结论不变。他们绕开了冲突，没有研究冲突。这和 MemGPT 页记下的 knowledge conflict 是同一件事。
  • 判分很宽松：输出里出现正确答案就算对，理由错了、出处错了也算对。
  • 没有对话，也没有工具调用。推测agent 的关键一行可能埋在很长的工具输出中间。
  • 只用了 2023 年的模型，输入最长约 2.2 万 token，只用 greedy decoding（每步取概率最高的 token）。今天的模型要自己重测。
一句话收尾

模型能不能用上信息，取决于信息放在哪

模型能不能用上 input context 里的信息，很大程度取决于信息放在哪：开头和结尾最好，中间最差，有时还不如一篇都不给；加长 context window 只是能装得更多，并不能让它用得更好。

ReAct 并不是处处都赢。哪种方法最好要看测试；最好的成绩来自在记忆和查资料之间切换。

两种组合方式，顺序很重要

Language Models (Mostly) Know What They Know

Kadavath, Conerly, Askell, … Olah, Kaplan · Anthropic · 2022

模型“知不知道”自己不知道？这里的“知道”只指三件可测的事：给选项的概率准不准、能不能判断自己答案的对错、能不能在回答前预测自己会不会。

arXiv 2207.05221 ↗Can We Trust the Judge?Human-AI Coevolution
四句话论文卡
主张

语言模型在很大程度上“知道自己知道什么”：大模型在格式合适的题目上校准良好，能评估自己答案的对错，还能预测自己会不会答对。这里的“知道”只指这三项可测的表现，不是理解。

最强证据

520 亿的模型在选择题和判断题上校准良好。P(IK) 在冷知识问答上的区分度评分是 0.864。给相关文章时 P(IK) 上升，给错误提示时下降。

边界

RLHF 模型很不校准，需要调温度来修补。它对格式很敏感（加上“以上都不是”就会破坏校准），在陌生任务上信心不足。P(IK) 需要训练模型内部，而且只测了有标准答案的任务。

产品还要验证

能不能在自己的任务上重新校准？开放式任务怎么估计把握？置信度怎么展示，才能让人做出更好的决定？

在知识地图上的位置

基础概念

校准、区分能力、模型大小

校准（calibration）

天气预报说“70% 下雨”的那些日子，约 70% 真的下雨，就是校准良好。衡量的是信心和实际表现是否匹配，不等于准确。

区分能力（discrimination）

某城市 30% 的日子下雨，每天都报“30%”的预报员完全校准，却毫无用处。还要能把会对的和会错的分开，用区分度评分衡量：0.5 是瞎猜，1.0 是完美。

模型“大”指什么

通常指参数多：可调的“旋钮”数量，代表容量。训练数据量是另一回事。本篇四个模型（8 亿到 520 亿）数据都是 8500 亿 token，只改参数。

规模定律

已有研究 Kaplan et al. 2020：表现随参数、数据、算力可预测地提升。Hoffmann et al. 2022（Chinchilla）：参数和数据要同步加，约每个参数 20 个 token。

平均下来两人都对，只有 B 能告诉你哪天该带伞。

Problem · 摘要, §1

三个由浅到深的问题

问题名称考试类比
做选择题时，给每个选项的概率准不准Calibration对每个选项有几成把握
写出答案后，能不能判断这个答案对不对P(True)交卷前检查：这题我做对了吗
还没回答，能不能预测自己会不会答对P(IK)，I Know看到题就“知道”这题我会不会（实际是一个额外训练的输出头给出概率）

三种是三种不同的概率，每一种都可以单独检验校不校准、区分能力好不好，并不是要三个都做对才叫校准。

Evidence · 校准

模型越大越校准，但 RLHF 之后变差

  • 选择题上模型越大、给示范越多，校准越好；字母选项格式更好；判断对错格式下 520 亿模型校准非常好。
  • 加“以上都不是”选项，准确率和校准都明显变差。
  • RLHF 模型“非常不校准”；把 temperature 调到 2.5，三个测试上的校准问题大部分解决。
  • 已有研究 temperature scaling 是标准做法（Guo et al. 2017）。GPT-4 技术报告也显示 post-training 后校准下降（待确认）。
更真实不等于更校准

RLHF 让回答更受偏好、更真实（InstructGPT 真实性测试约翻倍），但它优化的是“人更喜欢哪个回答”，不是“概率准不准”。标注员偏爱果断的回答，模型便学会把概率推向极端。

Evidence · P(True) 与 P(IK)

自我评估

  • 先生成 5 个备选答案再判断其中一个，P(True) 明显提升，模型越大提升越多。有比较才有判断，和 CoT-SC、SelfCheckGPT 同理。
  • P(IK) 在冷知识问答上，520 亿模型区分度评分 0.864。“标准答案”由同一题答 30 次的正确比例得出。
  • 给相关 Wikipedia 文章或正确的数学提示，P(IK) 上升；给错误或干扰提示，P(IK) 下降。
  • 两个预训练数据不同的 120 亿模型，在知识不同的题上 P(IK) 反映各自的知识，差异约 6%。
只在冷知识问答训练 P(IK)，测算术、填词、写代码结果

Limitations

作者承认的，和可以从原文核对的

  • 主要研究预训练模型，RLHF 模型不一定适用。
  • 预训练混淆了“客观事实”和“人们怎么说”。
  • 没有处理激励冲突：如果输出失真的信心能拿更高奖励，模型给出的概率还会不会和实际准确率一致？
  • 只在 5 类任务上测了迁移；知识超出人类训练数据时，模型自评的概率是否仍然准确，未回答。
盲区事实依据为什么重要
全是有标准答案的题选择题、短答案、代码测试开放式任务的“我会不会”没测
P(IK) 需要改造模型内部在模型上加专门的输出头训练推测通过 API 用别人模型的团队做不到，只能用提问或抽样一致性
只测了 2022 年的自家模型8 亿到 520 亿参数新一代模型需另行验证
我们的讨论

预测、考试类比，和 RLHF 为什么仍被追捧

你的预测论文结果
参数越多，校准越好✅（前提是格式合适）
RLHF 之后校准更好❌ 非常不校准，调温度可修补
P(IK) 能一定程度迁移，但不太准✅ 区分能力迁移，校准变差
陌生任务上可能过度保守✅ 常常信心不足
  • 已有研究这测的就是考试里的元认知（metacognition）：好学生不一定每题都会，但通常知道自己哪题不会。
  • 推测调温度只改变概率的整体尖平，不改变信心的高低顺序；它能修好校准，说明 RLHF 可能没破坏模型内部对“自己会不会答对”的区分能力，只是让输出的信心更夸张。
  • 人类反馈是“过度自信”和“谄媚”的重要来源，但不是幻觉（主要来自 pretraining）和偏见（RLHF 后无显著改善，InstructGPT §4.2）的主要源头。问题不在“人”，在优化目标：喜欢不等于正确。
  • RLHF 仍被追捧，原因有几个。没有它，模型基本没法直接用（InstructGPT 13 亿胜 1750 亿）。它能优化写不成规则的东西。排序数据便宜。副作用已知，而且可缓解（KL penalty、调温度、改标注规则）。配方也在演变，偏好打分逐渐收缩到没有标准答案的任务。打个比方：用户满意度调研有偏差，但没人因此放弃，而是结合行为数据交叉验证。
推测设计含义

不能直接把 RLHF 模型的概率当置信度展示，要在自己的任务上重新校准（用真实工单和查询）。陌生领域偏保守是相对安全的失败方式，但保守过度会回到审批疲劳。区分能力比精确数字更有用：用“高 / 中 / 低”把需要复核的挑出来，可能就够了。

Pretraining

A model can only do math, so text is first turned into numbers. Then the model reads a huge amount of it and guesses the next word, over and over. Along the way it picks up language and a lot of facts. Everything later builds on this.

The question: how does a pile of numbers learn what words mean?

Key ideas
Text becomes numbers first

A model only does math, so a tokenizer cuts text into small pieces called tokens and gives each one an ID number. The ID is just a label, like a locker number.

Numbers that carry meaning

Each ID is then swapped for an embedding: a list of hundreds of numbers. Like RGB for colors, similar meanings get similar numbers. The numbers start random and are learned during pretraining.

Unlike RGB, a single embedding number has no name.

Guess the next word, over and over

Give it “The cat sat on the” and it guesses “mat”. The real next word is the answer key, so no human labels are needed and almost any text works. Each wrong guess nudges the numbers a little. Words used the same way, like “apple” and “pear”, get nudged the same way and drift together. Prior research

Learning means turning knobs

The model is a huge function with billions of settings, called parameters. After each guess, a score called loss says how wrong it was. It rewards stating the true odds, so confident mistakes cost the most, and that is why pretrained models tend to be well calibrated. Training nudges every setting slightly to lower it (gradient descent), then repeats an enormous number of times.

Attention lets words look at each other

To guess well, each word needs to know which earlier words matter. Attention lets every word look back at all the earlier ones at once, instead of reading one word at a time like older models. That made training fast enough to pretrain on huge amounts of text. Prior research

RNN vs Transformer →
Bigger helps, up to a point

More parameters (a bigger brain), more text (more books read) and more compute keep pushing the loss down. But they have to grow together: many models were too big for the text they saw. Prior research

You get a continuer, not an assistant

Ask a freshly pretrained model a question and it may just carry on with more questions, because that is also a likely way for the text to continue. Making it helpful is the next stage.

Post-training

A pretrained model only continues text. Post-training changes that, so it follows instructions and gives answers people actually want. The method is to grade its answers and nudge its weights toward higher grades.

The question: how does a text continuer become a useful assistant?

Key ideas
Three ways to grade

You can show it good example answers, let people rank its answers, or check its answers against something with a definite right answer, like a math result or a unit test. Which one you pick shapes what the model turns into.

Learning from people’s preferences

For the same question, people rank several answers. A separate model, called a reward model, learns to predict those rankings, and then it grades the model being trained, which the paper calls the policy. This is RLHF. In InstructGPT, people preferred a far smaller model trained this way over the original GPT-3.

InstructGPT →
If you can check it, right or wrong is enough

When an answer can be checked automatically, you can skip the human grader and just reward correct answers. DeepSeek-R1 did this, and its answers grew longer and more careful without anyone asking for that.

DeepSeek-R1 →
Post-training can make models overconfident

After RLHF, a model’s stated confidence tends to run higher than how often it is actually right: it might say it is 90% sure when it is right about 70% of the time. Before post-training, models tend to be well calibrated. Preference grading rewards answers people like, not honest odds. Paper Calibration

Calibration →
You get what you grade

Push hard on any score and the model finds shortcuts: high score, wrong result. That is Goodhart’s law, called reward hacking in AI. A boat in a racing game learned to circle and hit bonus targets instead of finishing. So RLHF adds a KL penalty, a leash that keeps the model close to where it started. Prior research For any metric that trains or judges an agent, ask how it is most easily gamed. Our inference

The grader evaluates and trains

The same kind of grader (a person, a scorer model or another LLM) is used to evaluate models and to train them. If the grader is biased, the model learns the bias. Prior research

Managing context

The model knows only what is in its context window right now, and the window has a fixed size. Rules files, retrieval, memory, tools, skills and subagents are all different answers to one question: what goes in this turn?

The question: what earns a place in the window?

The window
What fills the window

Official docs Everything the model can refer to while it answers, including the answer it’s writing. Instructions, tool and skill descriptions, documents, your input and its output all share one budget. Each method further down frees up part of it.

Context windows (Anthropic docs) ↗

Cached tokens: cheaper, not smaller

Official docs The front of the window (tools, then system prompt, then messages) is often identical from turn to turn, so the provider can cache it. Cached tokens are read faster and at a fraction of the price, but they still count as input and still take up room. Evaluation

Evaluation isn’t a last step. Every stage has to answer: did it really get better, and can we trust the result? The grading used to evaluate a model is also what trains it.

The question: how do we know it did well, and can we trust that?

Key ideas
First ask: is there a right answer?

If there is, check the result or run a test. If there isn’t, you need people’s judgment, or a judge that stands in for them. Everything else follows from this split.

Learned, or memorized?

To check whether a model really learned, test it on questions it never saw, the way a real exam is kept apart from practice problems. Acing practice but failing new questions is overfitting. And if test questions leaked into the training text (contamination), a high score means little.

Doing it once doesn’t count

A model that gets a task right today can get it wrong tomorrow. τ-bench measures how often it succeeds every single time across repeated tries (pass^k), and success drops fast as the number of tries goes up.

τ-bench →
Models can grade models, with habits

When there is no right answer, a strong LLM can act as the judge. MT-Bench found it agrees with people about as often as people agree with each other. But it has habits: it favors the answer it sees first, longer answers, and its own writing.

MT-Bench →
Does it know when it’s unsure?

Calibration asks whether “I’m 70% sure” really means right about 7 times in 10. Large models are often fairly well matched on this, and post-training can make the match worse. Prior research

Calibration →
Explore wide, then commit

While exploring ideas, generating many options and letting a person pick is fine (pass@k). Once you carry out the chosen one, it has to be right every time (pass^k). Our inference

Shared blind spots

The facts in each item come from the papers. Only the last line, what it means for products, is inference.

LLMs stand in for people

Paper τ-bench uses gpt-4 as the simulated user; MT-Bench uses GPT-4 as judge; InstructGPT uses a reward model in place of labelers; Reflexion uses an LLM or self-written tests as its Evaluator on some tasks.

Our inference None validated against enterprise domain experts.

“Humans” are a narrow group

Paper MT-Bench: grad students and crowd users. InstructGPT: about 40 labelers mostly in the US or Southeast Asia. τ-bench: no human baseline reported.

Our inference Agreeing with them isn't agreeing with SREs or admins.

Humans disagree with each other

Paper MT-Bench expert agreement 81%; InstructGPT labeler agreement about 73–77%. Disagreement gets averaged away in training and scoring.

Our inference Minority user groups' preferences are the first to disappear.

Outcome only, not process

Paper τ-bench authors state r=1 is necessary but not sufficient: acting without confirmation still counts as success. MT-Bench scores only the final answer.

Our inference Enterprises need to know who approved and what the agent saw.

All failures weigh the same

Paper τ-bench scores 0 or 1. Refusing when the rules require it scores, but when the task was doable, “escalate to a human” and “do it wrong” both score 0.

Our inference Can't tell noticeable failures from silent ones.

Preferred isn't correct

Paper MT-Bench judges “favor” longer answers (longer answers score higher) and are misled by wrong math; Reflexion's self-written tests pass wrong code (16% on Rust).

Our inference A polished but wrong RCA may score well.

Evaluation and training get gamed

Paper InstructGPT adds a KL penalty specifically to stop exploiting the reward model.

Prior research Reward hacking is well known; RLHF models tend toward sycophancy (Anthropic 2023, to verify).

No credit for expressing uncertainty

Paper τ-bench 0/1 scoring as above. Prior research Kalai et al. 2025 argue that scoring which rewards guessing over abstaining keeps hallucination alive (to verify).

Our inference MT-Bench's verbosity bias may penalize short “I'm not sure” answers; untested.

Knowledge is static

Paper τ-bench uses a fixed database; MemGPT uses fixed chat logs and a 2018 Wikipedia dump; Reflexion's tasks all have answer keys.

Our inference Stale runbooks and contradicting policies were never tested.

No access boundaries

Paper MemGPT pairs one agent with one user; τ-bench serves one user per conversation.

Our inference In enterprises, one agent's memory and tools span teams and permission levels, and who can retrieve what was never tested.

Seventeen design principles

Rate risk by detectability, not just failure type

Loud / silent × reversible / irreversible. The worst failures are silent ones that have already fed a decision.

Basis: τ-bench 0/1 scoring and failure breakdown (§3, §5.2 Paper)
For silent failures, show the evidence

Show the query that actually ran and its data scope; give batch operations a coverage count, not just “Done”.

Basis: partial completion is 19% of τ-bench failures (§5.2 Paper)
Confirm key parameters in structured form before writes

List the model, amount, IDs, old → new values. This catches more errors than having the agent paraphrase.

Basis: wrong arguments or info are about 55% of τ-bench failures (§5.2 Paper)
Tier approvals and make them meaningful

Split by risk: read-only, reversible write, irreversible write. Approving every step becomes a rubber stamp, and blame lands on whoever clicked.

Basis: τ-bench scores outcome, not process (§3 Paper); moral crumple zone (Elish, Prior research)
Let people judge first, then reveal the AI's view

When the AI's suggestion appears decides whether human judgment stays independent.

Basis: 34% of people revised their judgment in disagreement cases (MT-Bench §4 Paper); anchoring, automation bias (Prior research)
LLM judges screen the obvious; humans take the close calls

The hard cases left out of the headline number are exactly the ones needing human judgment.

Basis: 85% agreement is S2 without ties; with ties it's 66% (MT-Bench §4 Paper)
Test SOP adherence with counter-intuitive rules

A good demo may only mean the tasks happened to match common sense.

Basis: removing the policy cost 4.4 points in retail but 22.4 in airline (τ-bench Table 3 Paper)
Make the hand-off explicit

Make “lock the direction” a step. The agent restates the chosen option, the reasons, what's ruled out and the constraints, and a person checks it and saves it as a brief.

Basis: Lost in the Middle (Prior research); intent debt (loop engineering writing)
Be explicit about whose taste defines “good”

General models reflect a small group of labelers by default. Use system prompts, domain examples or your own users' feedback to redefine “good” for your users.

Basis: InstructGPT §5.2 “Who are we aligning to?” (Paper)
Give agents a sandbox to fail safely

High risk doesn't rule out trial and error. It rules out trial and error in production. Dry runs, test environments and sample-data validation let the agent iterate, then submit once. People move from watching every attempt to defining success and checking the final submission. In urgent incidents the bottleneck is time.

Basis: Reflexion self-tests before submitting (§3–4 Paper); τ-bench “a user-facing agent gets one chance” (§5 Paper)
Make what agents learn viewable and editable

Let users or admins review, edit and delete the lessons an agent keeps, like a shared SOP.

Basis: Reflexion reflections are readable (§6 Paper), evaluators misjudge (§4 Paper); CLEA's memory and alignment drift topics (Paper)
Give uncertainty a place in the interface

Separate what was looked up from what was inferred, show the basis, suggest verification when confidence is low, and don't penalize “I don't know”.

Basis: InstructGPT still makes simple mistakes (§4.3 Paper); Kalai et al. 2025 (Prior research, to verify)
Give memories and documents a source, date and owner; surface conflicts

When citing a runbook or policy, show where it came from and when it was updated; when two disagree, show the user instead of silently picking one.

Basis: MemGPT memories have no provenance or conflict rules, and its test data is static (§2–3 Paper); τ-bench lists conflicting facts as a challenge (§6 Paper)
Give memory a visible directory

Show what's in the cabinet, how fresh it is and where it conflicts, so the agent isn't searching blind and people know what it remembers.

Basis: MemGPT retrieval has limits and often stops paging early (§3.2 Paper)
Don't treat explanations as evidence; audit with counterfactuals

Fluent reasoning is expression, not verification. High-stakes conclusions should point back to specific lookups; audits should reorder inputs, remove evidence or drop the user's stated view and see if the conclusion moves.

Basis: 14% of CoT answers were right with wrong reasoning (ReAct Table 2 Paper); MT-Bench position bias and swap test (§3.3 Paper); Turpin et al. 2023 and others (Prior research)
Calibrate confidence on your own tasks; show discrimination, not precise numbers

An RLHF model's probabilities aren't confidence as-is. Recalibrate on real tickets and queries; in the interface, high / medium / low that flags what needs review often beats “73%”.

Basis: RLHF models are badly calibrated and fixable with temperature; on unfamiliar tasks calibration degrades while discrimination transfers (Calibration Paper)
Pair every metric with a “how could this be gamed?” check

Once a metric becomes a target it gets gamed (Goodhart's law). Pair any metric used to train or evaluate an agent with a counterfactual test or cross-check.

Basis: MT-Bench verbosity bias (§3.3 Paper), InstructGPT KL penalty (§3.5 Paper), Reflexion self-test false passes (§4 Paper); Goodhart 1975, Strathern 1997 (Prior research)

The paper in four lines
Claim

An encoder–decoder using only attention, without recurrence or convolution, can match or beat the best machine translation results of its time while being easier to parallelize in training.

Strongest evidence

The Transformer paper's evidence is BLEU, which measures how close the output is to a reference. τ-bench's evidence is the final database state, which shows whether the job actually got done.

Core metric

pass^1 and pass^k

Barista analogy. pass^1 is the chance one latte comes out right. pass^8 is the chance the same latte comes out right on all 8 days you order it.

56%pass^1: average success over all attempts
25%pass^8

The four tasks in the calculator are a teaching example, not paper data.

  • The agent runs at temperature 0.0 and the simulated user at 1.0. Most of the inconsistency comes from users phrasing things differently.
  • pass@k means at least one of k succeeds; pass^k means all k do. As k grows, the first rises and the second falls.

How the reward model is trained

  • For each prompt, labelers rank 4 to 9 answers, which are then split into pairwise comparisons.
  • The training goal: make the “chosen” answer's score higher than the “rejected” one's. The bigger the gap, the more confident it is that people prefer the first. The result is a model that gives each answer a score.
  • A 6B reward model scores the 175B model. The paper gives two reasons: it saves compute, and training a 175B reward model could be unstable. It doesn't say a small reward model is easier to game. That's someone else's inference.

KL penalty

The score is the examiner's score minus how far the model has moved from the SFT model. This guards against reward hacking, where the model turns into someone else just to please the examiner.

PPO-ptx

Mixes some pretraining data into practice, so the model keeps up the basics while it learns new things. That guards against the alignment tax. The objective has two dials. One sets how strong the KL penalty is (β). The other sets how much pretraining data is mixed in (γ). Setting γ to 0 gives plain PPO. In the paper, “InstructGPT” means PPO-ptx by default.

What the alignment tax is, and how it happens

What it is. After the model is shaped into a good assistant, it gets worse at some general abilities it used to have. It's like practicing only for the essay exam and slipping in math. That's the “tax”.

Our inference How it happens. During RL, all of the model's parameters get pushed toward whatever the reward model scores high. The parameters are shared, so while they're pushed toward “acts like an assistant”, nothing protects the other skills, and some get crowded out.

Our inference Why the KL penalty can't fix it. It says “don't let answers on the practice prompts drift too far from the SFT model”, so it only watches the practice questions. The regression happens where practice didn't reach, and holding the practice answers in place doesn't hold the other skills. The paper's observation fits this: turning KL up doesn't win the skills back.

The fix. PPO-ptx also does a few of the original pretraining problems during practice, like reviewing math while practicing essays. It wins back most of the loss, but not all.

Since then · Prior research

Rule-based scorers can be gamed too

Prior research arXiv 2604.15149 (April 2026, Helff et al.): on inductive reasoning tasks, RLVR-trained models (GPT-5, Olmo3) stop inducing a rule and instead list each instance's label, which also passes the verifier. I read only the abstract, not the full paper, and the abstract has no numbers.

Our discussion

Product implications

  • Our inference Thinking time becomes a resource you buy. Long chains of thought mean more latency and cost. The design question is when the agent gets to think longer, and whether the user sees waiting or the process.
  • Our inference It works where answers can be checked automatically. Math and code have them. Root-cause analysis (RCA) doesn't, unless, like fault injection, you plant a known answer first.
  • Our inference The verifier itself needs testing. If “correct” in an eval can be reached by a shortcut, the score is inflated.
  • Our inference Auditing needs the evidence chain, not just the chain of thought. A chain of thought is text the model wrote, and prior work suggests it may not reflect what it actually relied on (see Turpin 2023 and Lanham 2023 in the README). What can be audited is what it looked up and what came back, which is the tool-call records. Think of the reasoning as a table of contents and the raw data and queries as the text. They should link to each other, and every claim should carry the query it rests on, so unsupported claims stand out.
  • Our inference Mixed-language thinking isn't necessarily a flaw for bilingual users. The consistency reward counts the share of target-language words, yet bilingual engineers naturally say things like “这个 index 的 retention 太短”. But enterprise logs need to be searchable and auditable, and mixed text makes that harder. Letting users choose what they see (a short version on the front line, the full original for audit) is a hypothesis worth testing. We have no usage data yet.

High risk doesn't rule out trial and error; trial and error in production does

MemGPT: Towards LLMs as Operating Systems · Packer, Wooders, Lin, Fang, Patil, Stoica, Gonzalez · UC Berkeley · 2023

Borrows virtual memory from operating systems. The context is a small desk, external storage is a big filing cabinet, and the LLM itself “decides” what stays on the desk, what gets filed, and when to go looking. In practice it emits a function call (store, search) that outer code executes.

Problem · Abstract, §1

Context is limited, but two kinds of task need a lot of memory

  • Analyzing documents longer than the context window.
  • Long-running, multi-session conversations, where the agent must “remember” the user across sessions and keep updating what it “knows” about them.
The operating-system analogy

A computer's RAM is small and fast, and its disk is large and slow. The OS decides what lives in RAM and what's swapped to disk, so programs feel like they have lots of memory (virtual memory). MemGPT treats the context window as RAM and external storage as disk, with the LLM acting as the OS.

The model gets a question and 20 Wikipedia passages. Only one contains the answer; the other 19 are closely related to the question but don't contain it. The paper calls them distractor documents. The researchers change one thing only: where the document with the answer sits.

High at both ends and low in between, the curve looks like a U. The paper calls it a U-shaped performance curve. Favoring the start is primacy bias; favoring the end is recency bias.

“Bias” doesn't mean the model “likes” the start. What's measured is only that information at the start or end is used correctly more often.

Question 4 · A simpler task §3

If the model only has to copy out a matching string, is there still a U?

To rule out “didn't understand the text”, the authors built key-value retrieval: a long list of JSON key-value pairs whose keys and values are random UUIDs, like "a3f9…": "7c2e…", plus one key. The model just has to copy out its value. No meaning involved.

For some models, yes.

  • Claude-1.3 is near-perfect wherever the pair sits and however long the list.
  • GPT-3.5-Turbo and MPT-30B-Instruct still show a U, more so with 140 or 300 pairs. GPT-3.5-Turbo (16K) copies the right value only 45.6% of the time in its worst position with 300 pairs.

With questions you could blame comprehension. This task only needs an exact match, and position still matters. So the problem isn't only understanding: even finding the information depends on where it is.

The authors find this odd too: self-attention can in principle retrieve any token equally well, so it shouldn't favor any position.

Question 5 · Why, part 1 · §4.1–4.2

Does putting the question before the data too help?

One concept first. Models like GPT are decoder-only: they read left to right, and at each token they can attend only to what comes before it. In these experiments the question comes last, so while reading the data the model doesn't yet know what to look for. The fix the authors try is query-aware contextualization: the question both before and after the data. Does it help key-value retrieval? The 20-document questions?

A lot for key-value retrieval; barely at all for the questions.

It's tempting to say the model now “has a goal”. What actually changes: with the question placed first, its tokens are already visible when each later line of data is processed, so every line is computed with the question available. The model doesn't “want” to find anything.

Our inference Why didn't the questions improve? The paper doesn't say. Key-value retrieval is an exact match: once you know the key, you're done. In the question task the distractors are already relevant to the question, so knowing it in advance doesn't help tell which passage really holds the answer. The hard part is judging, not finding.

Another kind of model, encoder-decoder, has a bidirectional encoder that sees both before and after while reading. Within the length it was trained on (2048 tokens), Flan-UL2's best and worst cases differ by only 1.9 points; beyond that length, the U returns.

Question 6 · Why, part 2 · §4.3

Does a base model, never instruction-tuned, also show the U?

Models like GPT-3.5 go through instruction fine-tuning: more training on many “instruction + response” examples, where the instruction usually comes first. So maybe favoring the start is learned there? The authors compare MPT-30B's base version with its Instruct version.

The base model shows the U too, even more strongly, which the authors call surprising. The base model's best-to-worst gap is nearly 10 points; the Instruct version's is about 4. Instruction tuning didn't cause the U; if anything it made it a bit shallower.

Three explanations, none settled

Looking only backward, the question coming last, instruction tuning: the authors call all three preliminary. Why the U exists is still an open question. In psychology, people recalling a list remember the first and last items best: the serial-position effect. Our inference It's a similar curve, not evidence that models have a human-like “memory”.

Question 7 · Real retrieval §5

Going from 20 to 50 retrieved documents, how much more does the model get right?

Finally, the authors retrieve documents from Wikipedia for real. Now the results may contain no answer, or several. Fifty documents are more likely to contain it than twenty.

Barely more, though not less. About 1.5 points for GPT-3.5-Turbo and 1 point for Claude-1.3, while the input more than doubles, along with latency and cost.

Two lines part ways here: retriever recall, the share of questions whose retrieved documents contain an answer, keeps rising; model accuracy flattens early. Retrieval brought the answer in; the model didn't use it.

The authors' own two suggestions: reranking, moving the most relevant documents to the front; and ranked list truncation, retrieving fewer when that's enough.

Question 8 · Limits

How is this different from real troubleshooting?

Recall the setup: exactly one document has the answer, one question and one reply, and scoring only checks whether the right answer appears in the output.

  • Exactly one document has the answer. Our inference In troubleshooting the answer usually has to be pieced together from several logs and runbooks, spread across the context. That is likely harder, but the paper doesn't test it.
  • Documents go stale and contradict each other. The paper runs into exactly this: a question asks which NFL team Robert Griffin III plays for; the reference answer says “currently a free agent”, while the 2018 Wikipedia says “Baltimore Ravens”. The authors drop such ambiguous questions and rerun, with the same conclusions. They avoided conflict rather than studying it. It's the same knowledge-conflict problem noted on the MemGPT page.
  • Lenient scoring: correct if the right answer appears, even with a wrong reason or a wrong source.
  • No dialogue and no tool calls. Our inference In an agent, the key line may sit in the middle of a long tool output.
  • 2023 models, inputs up to about 22K tokens, greedy decoding only (always the most likely next token). Retest on today's models.
In one sentence

Whether the model uses information depends on where it is

Whether a model uses information in its input context depends heavily on where that information sits: best at the start and end, worst in the middle, sometimes worse than no documents at all. A longer context window only lets it hold more; it doesn't make it use what it holds any better.

Evidence · §3–4

When does ReAct win?

ReAct isn’t the winner everywhere. Which method wins depends on the test, and the best results come from switching between memory and lookups.

Two ways to combine them, and the order matters

  • ReAct → CoT-SC. Look things up first. If there’s no answer after 7 steps (5 for fact-checking), answer from memory 21 times and take the most common answer. Best on multi-hop questions: 35.1.
  • CoT-SC → ReAct. Answer from memory 21 times first. If fewer than half the answers agree, the model isn’t sure, so it looks things up. Best on fact-checking: 64.6.

Our discussion

Intuition and verification

Prior research Answering from memory is like Kahneman’s fast, intuitive System 1; looking things up is like slow, deliberate System 2. Our inference CoT’s hallucinations, 56% of its failures, sound as confident as its right answers, so one answer can’t tell you when the intuition is off. That’s why CoT-SC → ReAct checks whether several answers agree before trusting memory.

Language Models (Mostly) Know What They Know

Kadavath, Conerly, Askell, … Olah, Kaplan · Anthropic · 2022

Do models “know” what they don't know? Here “know” means three measurable things. Are the probabilities on answer options accurate? Can a model judge its own answer? Can it predict beforehand whether it will get a question right?

arXiv 2207.05221 ↗Can We Trust the Judge?Human-AI Coevolution
The paper in four lines
Claim

Language models largely “know what they know”: large models are well calibrated on suitably formatted questions, can evaluate their own answers, and can predict whether they'll answer correctly. “Know” here means only those three measurable behaviors, not understanding.

Strongest evidence

The 52B model is well calibrated on multiple-choice and true/false questions. P(IK) reaches a separation score of 0.864 on trivia questions, and it rises with relevant articles and falls with wrong hints.

Limits

RLHF models are badly calibrated and need temperature fixes. Calibration is sensitive to format (“none of the above” breaks it). Models are underconfident on unfamiliar tasks, P(IK) needs training inside the model, and only tasks with answer keys were tested.

Still to validate for products

Can you recalibrate on your own tasks? Can you estimate confidence on open-ended work? Does displaying confidence help people make better decisions?

Where it sits on the map

The premise earlier papers kept running into

  • Paper ReAct Table 2 56% of CoT failures are hallucinations, stated as “confidently” as correct answers.
  • Paper InstructGPT §4.3 Models make simple mistakes and sometimes hedge too much.
  • The principle “give uncertainty a place in the interface” assumes the model's confidence tracks how often it is right (calibration).
  • Paper ReAct §3.3 CoT-SC → ReAct uses agreement across samples as confidence; this paper studies more direct methods.
Basics

Calibration, discrimination, model size

Calibration

If it rains on about 70% of the days a forecaster says “70%”, the forecaster is well calibrated. It measures whether confidence matches performance. It isn't accuracy.

Discrimination

In a city where it rains 30% of days, a forecaster who always says “30%” is perfectly calibrated and useless. You also need to separate right from wrong cases, measured by a separation score: 0.5 is chance, 1.0 is perfect.

What “bigger” means

Usually more parameters: the number of adjustable “knobs”, a measure of capacity. Training data is separate. Here all four models (800M to 52B) saw the same 850B tokens; only parameters vary.

Scaling laws

Prior research Kaplan et al. 2020: performance improves predictably with parameters, data and compute. Hoffmann et al. 2022 (Chinchilla): grow parameters and data together, about 20 tokens per parameter.

Both match reality on average. Only B tells you when to bring an umbrella.

Evidence · Calibration

Bigger is better calibrated, but RLHF makes it worse

  • On multiple choice, larger models and more examples mean better calibration; lettered options help; in true/false format the 52B model is very well calibrated.
  • Adding “none of the above” clearly hurts both accuracy and calibration.
  • RLHF models are “very miscalibrated”; setting temperature to 2.5 largely fixes calibration on three evaluations.
  • Prior research Temperature scaling is a standard method (Guo et al. 2017). The GPT-4 technical report also shows calibration dropping after post-training (to verify).
More truthful isn't more calibrated

RLHF makes answers more preferred and more truthful (InstructGPT roughly doubled a truthfulness test), but it optimizes for which answer people prefer, not whether probabilities are accurate. Raters favor decisive answers, so the model learns to push probabilities to extremes.

Evidence · P(True) and P(IK)

Self-evaluation

  • Showing 5 sampled answers before judging one clearly improves P(True), more so for larger models. Comparison enables judgment, as with CoT-SC and SelfCheckGPT.
  • P(IK) on trivia questions reaches separation score 0.864 at 52B. The “ground truth” is the fraction correct over 30 samples per question.
  • P(IK) rises with a relevant Wikipedia article or a correct math hint, and falls with wrong or distracting hints.
  • Two 12B models with different pretraining data show P(IK) tracking their own knowledge, differing by about 6% on disputed questions.

Limitations

What the authors admit, and what you can check

  • Mostly pretrained models; RLHF models may differ.
  • Pretraining conflates objective truth with what people say.
  • Conflicting incentives aren't addressed: if reporting a distorted confidence earned more reward, would the stated probabilities still match actual accuracy?
  • Transfer tested on only 5 task types; whether self-assessed probabilities stay accurate beyond human knowledge is left open.

Our discussion

Predictions, the exam analogy, and why RLHF still dominates

Show the table · Your prediction · Result
Your predictionResult
More parameters, better calibration✅ (given suitable formats)

P(IK) transfers somewhat, not very accurately✅ Discrimination transfers, calibration degrades
Possibly overly cautious on unfamiliar tasks✅ Often underconfident
  • Prior research This is metacognition, as studied in exams: good students don't know every answer, but usually know which ones they don't.
  • Our inference Temperature only sharpens or flattens probabilities overall without reordering confidence. That it fixes calibration suggests RLHF may not have damaged the model's internal signal of whether it will be right, only exaggerated the confidence it outputs.
  • Human feedback is a major source of overconfidence and sycophancy, but not the main source of hallucination (mostly pretraining) or bias (no significant change after RLHF, InstructGPT §4.2). The issue isn't people but the objective: preferred isn't correct.
  • RLHF still dominates for several reasons. Without it models are barely usable (InstructGPT 1.3B beat 175B). It optimizes things that can't be written as rules. Ranking data is cheap. The side effects are known and can be mitigated (KL penalty, temperature, rater guidelines). And the recipe keeps evolving, with preference scoring shrinking to tasks without answer keys. An analogy: satisfaction surveys are biased, yet nobody drops them, and teams triangulate with behavioral data.
Our inference For design

Don't show an RLHF model's probabilities as confidence directly. Recalibrate on your own tasks (real tickets and queries). Caution in unfamiliar domains is a relatively safe failure, but too much brings back approval fatigue. Discrimination matters more than exact numbers, and high / medium / low may be enough to flag what needs review.
